Factory Inventory Management

A Vue 3 single-page app talking to a FastAPI service over JSON. Data is loaded from JSON files into memory at startup, with no database. All changes are lost on restart.

System architecture

Tech stack

Frontend

  • Vue 3 Composition API, vue-router 4
  • Vite 8 with @vitejs/plugin-vue
  • axios for HTTP
  • Hand-built SVG and CSS charts, no chart library

Backend

  • Python 3.11+, FastAPI, uvicorn
  • Pydantic 2 models
  • pytest with FastAPI's TestClient, in tests/backend

Data

  • JSON files in server/data
  • Loaded once at import time
  • Open CORS and no auth: local demo only

Data flow: changing a filter

  1. FilterBar.vue updates a ref held in the useFilters singleton, so every view shares it.
  2. The active view's watch fires and calls its load function with getCurrentFilters().
  3. api.js builds query params, dropping any filter set to all.
  4. FastAPI applies apply_filters and filter_by_month to the in-memory lists, then aggregates if needed.
  5. The JSON response lands in a ref. Computed properties derive totals and chart data, and the template re-renders.

Data flow: placing a restocking order

  1. Moving the budget slider requests GET /api/restocking/recommendations?budget=N.
  2. The server computes each SKU's shortfall (forecast minus stock on hand), sorts by trend and growth, and fills the budget from the top, allowing partial lines.
  3. Place Order sends POST /api/restocking/orders with SKUs and quantities only. The server re-prices the order and rejects it if it is over budget.
  4. The Orders view reads GET /api/restocking/orders for its Submitted Orders section. Delivery lead time is that of the slowest line.

Known gaps

  • Purchase orders are unfinished: the Dashboard's Create PO button opens nothing because PurchaseOrderModal doesn't exist, and api.js has PO methods with no server routes.
  • orders.json repeats ids and order numbers for ten orders (ids 201 to 210), so GET /api/orders/{id} can't reach the second of each pair.
  • Eight of the nine forecast SKUs are not in inventory.json. Restocking treats them as out of stock.
  • unit_cost and lead_time_days on forecasts are mock values added for the Restocking feature.
  • The API base URL is hardcoded to localhost:8001.
